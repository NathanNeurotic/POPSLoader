## X-38 ruling (adjudicated from the PS2-Servers clone, `c5f021c4d386`)

**Question:** old final (VERIFIED) says Go zeroes "timestamps and attrs … the other editions fill"; redo's verification (RE-X-10 → WEAKENED, final scope "timestamps only") says Python hard-codes attr 0 in every stat path, so the attr half is not a divergence.

### (a) Timestamps — OLD is right; redo agrees. Divergence REAL.

- Go `native/ps2servers-edge/internal/udpfs/operations.go`: `sendOpen` (`:464-472`) allocates the 36-byte OPEN_REPLY and writes only result/mode/size/hisize — bytes 20–35 (ctime/mtime) are never written. `sendDRead` (`:748-765`) writes name_len/result/mode/size/hisize only — bytes 24–47 (ctime/atime/mtime) never written. `sendGetStat` (`:809-816`) same. No PS2 time encoder exists anywhere in the Go UDPFS tree (grep: no `encodeTime`/`ps2Time` in `internal/udpfs/*.go`).
- Python `udpfs_server/udpfs_server.py`: `_stat_to_bytes` (`:1451-1468`) fills `'ctime': self._encode_time(st.st_ctime)`, `'atime': …(st.st_atime)`, `'mtime': …(st.st_mtime)` with real filesystem times (`_encode_time` at `:1435-1449` packs the PS2 8-byte format); `_get_compressed_stat` (`:1388-1403`) does the same. The reply builders emit them: `_send_open_reply` (`:3045-3062`, ctime+mtime appended), `_send_dread_reply` (`:3109-3140`), `_send_getstat_reply` (`:3142-3160`).
- Therefore a client sees real dates from Python and epoch zeroes from Go Edge, exactly as both finals' surviving scope states. (Redo's further caveats stand and are consistent with old's fix being non-trivial: DREAD's Go `DirEntry` carries only `ModTime` — `internal/session/session.go:43-53`, clone-verified — and most Go OPEN paths never stat, so full parity is new code; mtime parity is the small fix.)

### (b) Attr — REDO is right; OLD is wrong. Attr limb NOT-REAL (no divergence).

- Python hard-codes attr 0 in **every** stat producer: `_stat_to_bytes` returns `'attr': 0` (`udpfs_server.py:1461`); `_get_compressed_stat` returns `'attr': 0` (`:1397`); the block-device stat dict is `'attr': 0` (`:2309`); and both reply builders' default stat dicts are `'attr': 0` (`:3116` in `_send_dread_reply`, `:3146` in `_send_getstat_reply`). Every DREAD/GETSTAT reply Python sends therefore carries attr **0** — byte-for-byte identical to Go's never-written zero at offset 12 of `sendDRead`/`sendGetStat`.
- OPEN_REPLY has **no attr field at all** in either edition: Python's `_send_open_reply` packs `'<BBBBiIII'` (handle, mode, size, hisize) plus ctime and mtime — there is no attr slot for Go's `sendOpen` to leave zero in. Old's location line for X-38 ("48/36-byte buffers with time/attr fields left zero", §1.2) is therefore wrong for the 36-byte reply as well as for the attr half generally.
- Old's claim that Python "fills real values" at `_send_open_reply:3045, _send_dread_reply:3109, _send_getstat_reply:3142` is true only of mode/size/times; at the attr offsets those same builders emit the hard-coded 0.

**Ruling:** X-38 survives only as a timestamps finding. RE-X-10's final (verification-narrowed) scope — "timestamps only; the attr half is not a divergence" — is the correct statement of the mechanism at the pin, and old's VERIFIED verdict on the combined "timestamps and attrs" headline does not survive its own clone evidence on the attr half.
