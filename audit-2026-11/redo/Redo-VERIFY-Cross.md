### RE-X-01 — UDPRDMA wire-controlled header length into fixed buffers — **VERIFIED**
Re-derived end-to-end: RiptOPL `udprdma.c:185` `hdr_size = data_hdr.hdr_word_count * 4` (4-bit field ⇒ ≤60 B) feeds `smap_fifo_read(0x30, s->rx_hdr_buffer, hdr_size)` (:193) and the `dummy[UDPRDMA_MAX_APP_HDR]` (32 B) skip branch (:196-197) with no clamp. `rx_hdr_size` is written only in `udprdma_set_rx_app_header` and **never read anywhere in RiptOPL's network tree** (full-tree grep); the sole app-header caller passes the 8 B `udpfs_msg_result_reply_t`. `smap_fifo_read` (xfer.c:106-157) has no internal clamp. SMS's clamp-and-drain exists exactly as described (`udprdma.c:198-215`, fill only when `hdr_size <= s->rx_hdr_size`, else drain in 32 B steps). Coordinator also read both files first-hand. Fix (port SMS's branch) is true and minimal. Duplication: CROSS-ASPECT-ONLY (defect filed per-repo as RE-RIPTOPL-005; RE-X adds the SMS fix source).
