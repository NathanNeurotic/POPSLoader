## Contradictions — full detail

### C-1 — cloud.html: "Automatic sync … is off by default" — the default mode is Local backup
- **Doc:** `docs-site/content/cloud.html:14` — "Automatic sync has three modes: *Off*, *Local backup*, and *Local + Google Drive*. **It is off by default**, applies only after an OPL game returns through the WLE-IGR helper…"
- **Code:** `src/dash_store.c:263-264` — `dashCfg.igr_auto_backup = 1; dashCfg.igr_cloud_sync = 0;` (defaults in `dashStoreDefaults()`), and the three-mode control is derived from exactly those two flags at `src/dash_settings.c:1163`: `*cur = !dashCfg.igr_auto_backup ? 0 : (dashCfg.igr_cloud_sync ? 2 : 1);` → a fresh configuration reads mode **1 = Local backup**, not 0 = Off. The DASHBOARD.CNF parser defaults agree (`src/dash_store.c:366-368`, defaults 1/0).
- **Corroboration that the doc side is the outlier:** four other pages state it correctly — `configuration.html:84` (defaults `1, 0, …`), `igr.html:26` ("default: Local backup"), `settings.html:117`, `mmce-backup.html:52`.
- **User impact:** a user who never touches the setting is told no automatic backup will happen; in fact every WLE-IGR return performs a local MMCE backup pass (when a destination is configured). Surprise writes + wrong mental model for the Drive-off half (Drive sync *is* off by default — `igr_cloud_sync = 0`).
- **Fix:** doc-side. Change cloud.html:14 to "Local backup by default (the Google Drive step is off until linked and selected)".

### C-2 — themes.html: panel-transparency direction is inverted
- **Doc:** `docs-site/content/themes.html:68` — "**Panel transparency**: **0% removes menu panels and 100% makes them fully opaque** (it edits the Panels colour's opacity)."
- **Code:** `src/dash_settings.c:252` help string — *"0% makes panels fully opaque; 100% makes them fully transparent"* — and the mapping is exactly that: getter `src/dash_settings.c:1290` `*cur = ((255 - dashTheme.panel.a) * 10 + 127) / 255;`, setter `:1374` `t->panel.a = (10 - v) * 255 / 10;` → 0% ⇒ alpha 255 (opaque), 100% ⇒ alpha 0 (transparent).
- **Correct side elsewhere:** `settings.html:41` — "0–100% (0% opaque; 100% transparent)".
- **User impact:** anyone hand-tuning via the Themes page does the exact opposite of what they intend; at 100% (believing "fully opaque") their panels vanish.

### C-6 — configuration.html: "Files larger than 128 KB are rejected" — the normal config load path has no size cap
- **Doc:** `docs-site/content/configuration.html:26` — "**Files larger than 128 KB are rejected.** A file without `CNF_version` is treated as a legacy config." (of `LAUNCHSTATION.CNF`)

- **User impact:** low — a user relying on the stated rejection as a safety/compat property (e.g. sharing one CNF with a stricter build) gets silent acceptance and full parsing of the oversized file on this build.
- **Fix:** either side — enforce the cap in the seekable branch of `preloadCNFFd()` (code-side, matches the documented contract), or soften the doc to the fallback/`dashLoadTextFile` scope.
