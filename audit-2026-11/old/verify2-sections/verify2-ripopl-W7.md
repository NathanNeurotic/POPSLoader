## Reasoning for non-VERIFIED verdicts

### RIPTOPL-348 — REFUTED

The finding claims: "whole-repo grep returns only the declaration plus the wrapper", "`raVcdBootName` alone is uncalled", and (in its Fix/Risk) "grep-proven no caller, incl. tests/".

Defeating evidence, at the pin:

- `.github/scripts/test_ra_ps1.py:137` — inside the generated C harness's `checks` string:
  `checks += f'assert(raVcdBootName("{file}",boot,sizeof(boot))==0 && !strcmp(boot,"{escaped}"));\\n'`
  emitted once per file for four VCD fixtures (`retail.vcd`, `nested.vcd`, `fallback.vcd`, `lower.vcd`, with expected boots `SLUS_012.15`, `D\G.EXE`, `PSX.EXE`, `slus_012.15`).
- That harness is not dead text: `test_ra_ps1.py:24-28` compiles the extracted `src/sources/rahash.cpp` plus the harness with `check=True` and runs the resulting executable with `check=True`.
- Executed by this worker at the pin: `python3 .github/scripts/test_ra_ps1.py` → exit 0, all PASS lines printed (including "PS1 hashes and stale-VCD guard…"). The four `raVcdBootName` assertions therefore execute and pass against the real wrapper (`src/sources/rahash.cpp:142-144`) and the real `RaHash::vcdBootName` method (decl `rahash.cpp:89`, def `rahash.cpp:826`).

So the free API and the method behind it have a live, executed caller — a test caller, not a production caller. The narrower truth is "no production (non-test) caller", which is not what was filed: the finding explicitly claimed the grep covered tests/ and returned nothing there. (The miss is understandable — the call sits inside a Python f-string with escaped quotes — but adversarially the claim as filed does not survive.) Deleting the declaration/wrapper/method as the finding proposes would break `test_ra_ps1.py`.
