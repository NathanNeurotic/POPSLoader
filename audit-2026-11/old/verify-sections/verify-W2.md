The suite itself also passes at the pin (`Ran 2 tests … OK`).

(The base `ps2.yaml` carries 72 targets; definition-time appends account for the rest.) The "none named `ps2sdk_socket_compat`, and no target's `libs` currently contains it" half of the claim does reproduce. Mechanism and conclusion unchanged; only the count is corrected.

### RIPTOPL-308 — WEAKENED (exit code is discarded, but the named crash scenario does not pass)

What holds, READ: `run()` at `test_save_icons.py:357-359` returns only `.stdout.strip()` from a `check=False` subprocess call; the harness return code is never read anywhere in the file (the only `returncode` use is the *compile* check at :354); the harness `main` returns 0 on every intended path (:343); the sibling form the fix cites (`test_smb_vmc_io_result.py:656-657`) does branch on `result.returncode`. Errors in the harness's model/card modes are indeed reported in-band as `ERR`/`NONE`.

What does not hold is the finding's residual scenario as stated — "a crash in `saveIconFreeModel`/`fclose` after `printf` … reports as a pass". The harness never flushes stdout and its output goes to a pipe, so glibc fully buffers it; a post-`printf` segfault or abort loses the buffered line entirely, the Python side sees `''`, and every call site's exact/`startswith` comparison then fails. This was executed with a minimal replica of `run()`'s capture shape: a program that prints the expected line and then segfaults yields `returncode=-11, stdout=''` (test fails), while the same program ending in a clean `exit(3)` yields `returncode=3, stdout='OK …'` (test would pass, code discarded). This is the same buffering rescue RIPTOPL-309's own text documents for its harness; RIPTOPL-308's text does not mention it.

Narrowed conditions under which the finding still bites: only a **clean non-zero exit after stdio has flushed** — `exit(n)`/`return n` from `main`, or an explicit `fflush` followed by `_exit`/signal — presents the expected stdout with a discarded non-zero status. No such path exists in the harness or in `src/gfx/saveicon.cpp` today (no `exit`/`abort`/`fflush`/`setvbuf` in either; `main` returns 0). So the gap is real but strictly narrower than filed: it is a missing belt-and-braces check with no currently reachable masking path, not a live post-print-crash pass. Verdict WEAKENED; the one-line fix the finding proposes remains correct and costless.
