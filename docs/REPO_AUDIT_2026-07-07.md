# POPSLoader Repository Audit — 2026-07-07

**Audited tree:** `BETA-13-PLAY` @ `be0647c`.
**Trigger (maintainer report):** "Some settings are contradictory, some need cwd defaults, some settings don't work, smb fails to connect even when I put in the right settings, and there are likely many other issues."
**Method:** a settings-inventory mapping pass, then 9 dimension finders (settings plumbing, setting-vs-setting contradictions, SMB C side vs OPL reference, SMB Lua/UI side, cwd defaults, UI rows end-to-end, boot-order, scripted runtime-trap sweeps, docs-vs-code) plus 4 critic-directed gap finders. 107 raw findings were deduplicated to **62 unique issues**, and every finding was adversarially verified against source (critical/high items by two independent verifiers). Verification outcome across the 107: **101 confirmed, 4 refuted, 2 disputed**. Refuted items are retained in the list (marked REFUTED) so they are not re-reported by future audits.

This is a REPORT with proposed solutions; no fixes have been applied. Every solution was checked against the preservation contracts (D-10/D-14/D-15 launch routes, `EnsureBootPartitionWritable`, BOOT.ELF/DKWDRV exit routes, embedded loader handoff, `reboot_iop` values) and none of the proposed fixes touch them.

## Executive summary

### 1. Why SMB fails to connect even with correct settings (the root cause)

**U02 — the connect code configures the wrong TCP/IP stack.** `EnsureNet` initializes the EE-side lwip stack (`ps2ipInit`), but the loaded `ps2ip-nm.irx` already registered the IOP-side stack with netman, and `smbman` uses only that IOP stack. The EE stack is silently orphaned (it never receives a single network frame), yet all IP configuration (static settings, DHCP arming, DNS) is applied to it. So on real hardware: DHCP can never bind (the OFFER arrives at a stack that is not wired to the driver), and static settings never reach the stack that matters, which sits at ps2ip's hardcoded 192.168.0.80/24 defaults. **Connect fails regardless of what the user types.** The fix is small and mirrors OPL exactly: call `ps2ip_init()` (the ps2ips RPC bind) instead of `ps2ipInit(...)`, after which the existing config calls automatically dispatch to the IOP stack. Needs a hardware test for the positive case.

**The Port=1111 default is NOT a bug (maintainer resolution, 2026-07-06).** The audit flagged it independently 14 times because standard SMB servers listen on 445; the maintainer confirmed 1111 is a deliberate ecosystem default matching his PS2-Servers custom-port setups. Remaining actions are alignment, not reversion: TESTING.md still says "Port (445)" (U12), README documents no SMB section at all (U33), a DECISIONS.md rationale entry should be added so future audits do not re-flag it, and the connect-failure toast should print the effective port so a port mismatch is self-diagnosable for standard-server users.

**Contributing SMB failures found while tracing the whole chain** (each independently breaks a "correct-looking" setup): trailing/leading spaces from the on-screen keyboard are never trimmed and are invisible in the UI (U08); the keyboard physically cannot type `@ # $ % * " < >` and other common credential characters (U14); a NetBIOS address-type option is offered that the C binding unconditionally rejects (U19 in list order U-numbered below as part of plumbing); errors misdirect (SMBv1-refused reports as "check User/Password", U22; a failed IP-config step reports as connection failure, U21); browsing works without the SMB module pack installed but launching then fails silently in-game (U07); the "Games path" setting browses a subfolder POPStarter can never launch from (U06); a blank-User-with-password config authenticates in the menu but omits credentials from SMBCONFIG.DAT (U26); share discovery can return blank names due to a DMA/cache hazard (U23); and the shipped template SMBCONFIG.DAT/IPCONFIG.DAT silently override in-app settings until the next save (U39).

### 2. Contradictory settings

- **Boot Page vs Internal HDD (U05/U18):** Boot Page cannot target the exFAT page at all, and a saved "HDD (PFS)" Boot Page silently does nothing every boot once Internal HDD is set to exFAT. Same silent-fallback class: Boot Page can point at a carousel-hidden device (U29).
- **Reset Defaults does not reset everything it owns (U04):** Internal HDD, Cover/details folder, and Carousel device visibility survive a "Reset Defaults".
- **Two different keyboard-layout defaults (U16):** fresh boot gives ABC, Reset Defaults gives QWERTY.
- **Failure toasts lie (U17):** a BDMA/SMB apply failure says "settings weren't saved / rolled back" when everything else WAS saved.
- **NetBIOS is offered but unsupported (U-NetBIOS below):** a selectable address type plus a text field that guarantee failure.

### 3. Settings that don't work

- **Internal HDD change is silently discarded on BACK (U03/U11):** it is missing from `HasUnsavedChanges`, so a lone PFS/exFAT flip gets no save prompt and vanishes.
- **CRLF sidecar wipe-out (U19):** a .pldrs edited in Windows Notepad silently reverts most settings to defaults (booleans, boot page, video standard all fail to parse with trailing `\r`).
- **POPSTARTER Folder OFF deletes the folder even when the settings save failed (U20)**, so the choice reverts next boot.
- **Any save failure force-exits Settings and destroys every draft edit (U28).**
- **Garbage values are silently reinterpreted (U35):** PORT="44S" connects to port 44, writes an implicit 445 to the .DAT, and displays "44S". Path editors save untrimmed strings whose failure is silent at launch (U36).
- **STRICT_HDD_PREEXEC_GATE is a ghost setting (U43):** persisted and consumed, no UI, undocumented.

### 4. cwd / boot-device defaults

- **usb:/ and smb:/ boots pin settings to a dead filesystem (U09):** settings load as defaults and every save fails; the sidecar exclusion list needs the same treatment HDD prefixes already get.
- **The POPSTARTER pack root is hardcoded to mc0: (U10):** slot-2-only consoles cannot install BDMA/SMB modules and their MC settings fallback fails.
- **DKWDRV default is mc0:-only (U27):** no cwd/app-dir probe, unlike POPSTARTER's custom→device→cwd→mc ladder; a DKWDRV.ELF next to POPSLOADER.ELF is not found.

### 5. Other notable finds

- **U15 (HIGH, genuine crash):** the launch-failure "returned after N ms" diagnostic crashes with a Lua format error (microsecond float into `%d`) exactly when a slow launch failure should show the diagnostic screen. One-token fix.
- **U30:** the busy-overlay repaint throttle compares microseconds to a 20 ms threshold, so large scans repaint+vsync every file (~8–10 s overhead on a 500-game device).
- **U40:** the new build-time Lua minifier shifts shipped crash line numbers up to ~483 lines from source; a line-preserving tweak (~600 bytes cost) makes shipped and source line numbers identical again.
- **U37:** Exit→OSDSYS from an HDD boot hands off with the boot partition still RW-mounted (PFS unclean-unmount corruption vector); the BOOT.ELF arm already does the teardown.
- **U53:** MMCE page with no device still enters an empty list (siblings return to the carousel).

## U01 [CRITICAL] Default SMB PORT is "1111", so SMB connect fails out of the box even with correct server/share/credentials
- loc: bin/POPSLDR/system.lua:3230 | found by: boot, gap1, plumb, rows, semantics, smb-c, smb-lua, traps (14x) | statuses: CONFIRMED, DISPUTED
- CLAIM: The shipped/reset default for the SMB Port setting is "1111" (PLDR.SMB_FIELDS, system.lua:3230), changed from "445" by commit 75e1a84 (2026-06-30) with no recorded rationale. lua_smb_connect (luasystem.cpp:1616-1620, 1662) uses the value verbatim as the SMB TCP port, so a user who fills in Server/Share/User/Pass correctly but leaves the obscure Port row at its default connects to server:1111, where no standard SMB server listens, and gets CONN_FAIL every time. The same default poisons the generated SMBCONFIG.DAT for POPStarter streaming: RenderSmbConfig (system.lua:4716-4721) emits an explicit ":1111" because only 445 is omitted as implicit. Everything else in the ecosystem treats 445 as canonical: the C-side fallback (luasystem.cpp:1603 int port = 445), the RenderSmbConfig comment (system.lua:4713-4714), OPL (gPCPort = 445, opl.c:1730), and the recovered POPStarter SMBCONFIG.DAT examples (no port suffix). This is the most likely root cause of the maintainer's "smb fails to connect even when I put in the right settings" report IF their server is on 445 and the Port row was left at default; if their own server deliberately runs on 1111 (a plausible unstated reason for 75e1a84), their specific failure has an additional cause, but the out-of-box failure for every standard-setup user stands either way.
- SOLUTION: First confirm with the maintainer why 75e1a84 set 1111 (personal server on a custom SMBv1 port?). Assuming no ecosystem-wide reason exists: revert the default to "445" in PLDR.SMB_FIELDS (system.lua:3230, a one-line revert of 75e1a84), and add a proper DECISIONS.md entry superseding the header-line mention. Do NOT auto-migrate persisted SMB_PORT=1111 sidecar values to 445 - if 1111 was set to match a real server, migration would silently break that working config; existing sidecars keep whatever they saved, only the shipped/Reset-Defaults value changes. Optional polish: when connect fails with CONN_FAIL and the configured port is nonstandard (not 445/139), append the port to the UI error message ("Connection failed (port 1111)") so a wrong port is self-diagnosable. No preservation contracts are touched (SMB is lazy, never on the boot path).

- **MAINTAINER RESOLUTION (2026-07-06): the 1111 default is DELIBERATE.** The maintainer runs SMB servers on custom ports via his PS2-Servers repository; 1111 is the intended ecosystem default, and his server listens where the client points, so this is NOT the cause of his connect failure (see U02 for the actual root cause). Remaining actions from this finding: align TESTING.md (U12), add the rationale to DECISIONS.md so future audits do not re-flag it, document the SMB section in README (U33) including a note that standard SMB servers listen on 445, and print the effective port in the connect-failure toast so a port mismatch is self-diagnosable. Do NOT change the default and do NOT migrate persisted values.

## U02 [CRITICAL] SMB IP config is applied to a dead EE-side lwip stack, never to the IOP stack smbman actually uses; connect can never succeed on hardware
- loc: src/luasystem.cpp:1458 | found by: smb-c (1x) | statuses: CONFIRMED
- CLAIM: EnsureNet (src/luasystem.cpp:1458) initializes the wrong TCP/IP stack: it calls the EE-side lwip initializer ps2ipInit(&ip_zero,...) instead of OPL's ps2ip_init() RPC bind. The loaded ps2ip.irx is ps2ip-nm.irx, whose _start already registered the IOP lwip stack with IOP netman (with hardcoded defaults 192.168.0.80/255.255.255.0 gw 192.168.0.1, since it is loaded with no args); IOP netman ignores the EE stack's later registration but still returns 0, so the EE stack is silently orphaned (never receives a frame). ps2ipInit also points libcglue's socket ops at that orphaned EE stack, and since ps2ip_getconfig/ps2ip_setconfig/dns_setserver are libcglue macros, SmbApplyIPConfig and SmbDhcpBound configure only the EE stack — never the IOP stack smbman actually uses. Result on hardware: DHCP mode arms DHCP on a stack that cannot receive the OFFER, so every connect ends in DHCP_FAIL after the 30 s poll; static mode leaves smbman's IOP stack at 192.168.0.80 defaults so LOGON's TCP connect fails (CONN_FAIL) on any network that doesn't happen to match that subnet — i.e. SMB connect fails regardless of the user's settings, exactly matching the maintainer report. CI can't catch it: both libs link cleanly.
- SOLUTION: Mirror OPL's ethLoadModules: in EnsureNet (src/luasystem.cpp:1452-1458) delete the three ip4_addr_set_zero lines, the ip_zero/mask_zero/gw_zero declarations, and the ps2ipInit call; call `if (ps2ip_init() < 0) return false;` instead. Add `#include <ps2ips.h>` inside the existing extern "C" block at luasystem.cpp:24-28 (keep `#include <ps2ip.h>` — struct ip4_addr, IP4_ADDR, ip4_addr_set_zero, ip_addr_set are header-only via common tcpip.h and still used by SmbApplyIPConfig), and update the stale comment at lines 20-23/1452-1453 that names ps2ipInit. In Makefile:51 remove `-lps2ip` from EE_LIBS (keep -lnetman -lps2ips). No other change: after ps2ip_init(), the existing ps2ip_getconfig/ps2ip_setconfig/dns_setserver macro calls automatically dispatch via the ps2ips RPC to the IOP stack smbman uses, and interface name "sm0" matches OPL. Touches only the lazy SMB bring-up; no preservation contract (launch paths, boot mounts, BOOT.ELF/DKWDRV routes, reboot_iop) is affected. Needs hardware verification for the positive case (PS2 + SMBv1 share).

## U09 [HIGH] usb:/ and smb:/ boots pin settings to a sidecar on a filesystem that does not exist inside POPSLoader - settings never persist
- loc: bin/POPSLDR/system.lua:2067 | found by: boot, cwd (3x) | statuses: CONFIRMED, REFUTED
- CLAIM: Boots whose argv0 carries a usb:/ or smb:/ (incl. smb0:) prefix compute a settings sidecar on a filesystem that cannot exist inside POPSLoader, so settings load as defaults every boot and every save fails.
