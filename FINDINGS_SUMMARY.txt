FINDINGS SUMMARY: POPSLoader HDD ELF Loading Silent Failure
================================================================================

OBJECTIVE: Find why HDD ELF loading fails silently (black screen, zero debug logs) 
in POPSLoader while other PS2 projects successfully load HDD-backed ELFs.

ROOT CAUSE IDENTIFIED:
The parent-context HDD ELF loading path (src/elf_loader/src/elf.c lines 627-898)
is architecturally broken because it violates a fundamental PS2 constraint:

  "RPC client connections created in one EE context become INVALID in another 
   EE context after ExecPS2."

================================================================================
ARCHITECTURAL CONSTRAINTS DISCOVERED
================================================================================

Constraint 1: RPC Context Loss on ExecPS2
  ExecPS2 switches EE context. Any RPC client connections created in parent
  become invalid in child. This is a fundamental PS2 architecture limitation.

Constraint 2: fileXioInit() Must Be Called in Execution Context
  fileXioInit() establishes an RPC connection. It MUST be called in the same
  context where fileXio operations will occur. It cannot be set up in parent
  and used in child.

Constraint 3: Module Loading Doesn't Cross Context Boundaries
  Modules loaded via SifExecModuleBuffer (IOP side) are global, but RPC client
  connections (EE side) are per-context.

Constraint 4: IOP Partition Mounting vs. EE RPC Client
  Even if a partition is "mounted" on the IOP side, the EE-side RPC client must
  be in the same context to use it. Parent's mount is useless to child if child
  has no RPC client.

EVIDENCE FOR ROOT CAUSE
================================================================================

Evidence 1: The Embedded Loader Works
  - Same codebase, different path
  - Only difference: fileXioInit() in correct context
  - Proves it's a context/RPC issue, not module loading issue

Evidence 2: wLaunchELF Avoids the Problem
  - Exits RPC before ExecPS2
  - Passes pre-mounted path to embedded loader
  - Both approaches acknowledge RPC cannot cross ExecPS2

Evidence 3: Silent Failure Pattern Matches RPC Loss
  - No debug output = fileXio not working (used for logging)
  - Black screen = POPSTARTER can't initialize (needs file access)
  - Perfect match for "RPC client lost after ExecPS2"

Evidence 4: SifLoadElf() Succeeds (Partial)
  - SifLoadElf() uses IOP's loadfile module (global)
  - Parent's SifLoadElf() works fine in parent context
  - But this doesn't matter once POPSTARTER runs with no RPC
